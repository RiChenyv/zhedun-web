# 这顿 校园用餐助手

手机访问：[https://richenyv.github.io/zhedun-web/](https://richenyv.github.io/zhedun-web/)

[分享二维码](https://richenyv.github.io/zhedun-web/assets/share-qr.png)

这是一个适合手机浏览器使用的纯前端交互样品，使用 GitHub Pages 托管，无需登录或安装应用。

## 可以体验什么

- 每顿个性化推荐：按近期消费、购买内容和获取习惯，推荐早餐、午餐、晚餐与夜宵，并解释推荐依据。

- 首页“帮我决定”：三步设定预算、时间和出门意愿，比较最快、最省、最少折腾的方案，查看推荐理由与取舍，直接预约。

- 42 道模拟餐食，按到手预算、等待时间、用餐方式和口味筛选，实时显示匹配数量。
- 对比价格、分量、等待时间和获取方式；收藏餐食或探索新口味。
- 选择规格、数量、预约时段，查看模拟订单进度、取餐码、取消订单和评价。
- 切换中国传媒大学梆子井公寓、校内公寓及中蓝公寓，默认梆子井公寓。
- 查看个人偏好、收藏和用餐记录，数据保存在当前浏览器。

## 演示说明

所有交易、商家资料、优惠、分量及出餐时间均为模拟，食物图片为 AI 生成的同类餐食示意图；不会产生真实支付或配送。图标统一使用手绘 SVG，不使用 Emoji。

换设备、换浏览器或换域名后，本地记录不会自动同步。新域名第一次访问会载入初始演示数据。

## 发布与本地预览

仓库 `main` 分支根目录是 GitHub Pages 发布源；`.nojekyll` 用于直接发布现成静态文件。页面使用 Hash 路由及相对资源路径，支持 `/zhedun-web/` 项目子路径。

通过静态 HTTP 服务预览，不要直接双击 HTML 文件，因为页面使用 JavaScript ES modules：

```text
python -m http.server 4173
```

## 文件

`index.html` 为入口，`app.js` 管理页面与交互，`data.js` 为模拟菜单，`model.js` 为计价、筛选和本地存储，`icons.js` 与 `styles.css` 提供图标和视觉样式，`assets/` 保存本地图片及分享二维码。

## 帮我决定：演示路线

首页四个快捷条件下方进入“帮我决定”，按预算、可用时间、出门意愿走完三步。结果按菜品与用餐方式计算，同一方案的推荐标签会合并。预算 ¥8、30 分钟、留在宿舍时可以演示增加预算的建议；预算 ¥60、15 分钟、留在宿舍时可以演示延长时间的建议。口味选择“都可以”，天气选择晴天。

决定条件与结果通过独立的 `zhedun-decision-v1` 会话记录保存，支持刷新与详情返回，普通菜单筛选和订单使用各自的存储。推荐为规则计算，不接入 AI、地图或业务后端。`decision.js` 管理推荐规则，`decision-ui.js` 和 `decision.css` 提供独立页面样式。

## 每一顿的个性化推荐

首页原来的“今日推荐”升级为早餐、午餐、晚餐、夜宵四个餐次的推荐。默认跟随设备本地时间：05:00—09:59 为早餐，10:00—15:59 为午餐，16:00—20:59 为晚餐，其余为夜宵；可手动切换，次日恢复自动。点击“推荐依据”或“我的 → 每顿推荐与依据”查看记录来源和习惯摘要。

推荐只分析当前浏览器近 30 天未取消的模拟购买记录，优先参考近 7 天及同餐次的购买；结合口味、餐食类型、获取方式和商家，近两天买过的菜适当降低顺序。消费统计只包含近 7 天已完成的订单，均价按总价除以份数计算，包含包装和配送；推荐价格仍受当前预算、可用时间、明确口味及用餐方式限制。早餐和正餐使用明确的模拟菜单餐次配置，不代表真实窗口营业能力。

初始两笔示例订单会明确标注，取消、异常、未来及超过统计期限的记录不参与相应分析。没有历史时先按偏好推荐；条件不满足时给出修改偏好或进入“帮我决定”的入口。推荐与记录仅在本浏览器计算，不读取其他平台订单；新订单、完成和取消会更新后续推荐。

推荐规则在 `personal.js`，界面与样式为 `personal-ui.js`、`personal.css`；独立会话键 `zhedun-recommendation-v1` 只保存当日餐次与轮换位置，不另存消费画像。首页保留原有筛选、比较及“帮我决定”专区。
